TrustPinConfiguration

public struct TrustPinConfiguration : Sendable

Configuration values passed to setup(_:).

try await TrustPin.setup(TrustPinConfiguration(
    organizationId: "your-org-id",
    projectId:      "your-project-id",
    publicKey:      "your-base64-public-key"
))

As an alternative to the programmatic initializer, ship the credentials in a bundled TrustPin and load them with fromPlist(_:fileName:) — see “Setup via TrustPin-Info.plist” in the README.

Bundle-based setup (TrustPin-Info.plist)

  • fromPlist(_:fileName:)

    Loads credentials from a TrustPin file bundled with the app.

    Ship a property list in the app target’s resources and resolve it at startup. Use one file per Xcode target for dev / staging / prod separation — no conditional code at the call site — or override fileName (with #if DEBUG, for example) when a single target needs to swap between files.

    try await TrustPin.setup(try TrustPinConfiguration.fromPlist())

    Plist schema

    Key Required Type Notes
    OrganizationId ✅ String Non-empty
    ProjectId ✅ String Non-empty
    PublicKey ✅ String Base64, same format the programmatic API accepts
    Mode ❌ String "strict" (default) or "permissive". Lowercase only — uppercase is rejected
    ConfigurationURL ❌ String Must be HTTPS. Empty string / missing → treated as not provided

    Unknown top-level keys are ignored for forward compatibility.

    Failure modes

    Every failure collapses to invalidProjectConfig. A descriptive line is written to stderr with the [TrustPin] prefix so the underlying reason is visible in the Xcode console.

    Throws

    invalidProjectConfig if the file is missing, unreadable, malformed, or fails schema validation.
