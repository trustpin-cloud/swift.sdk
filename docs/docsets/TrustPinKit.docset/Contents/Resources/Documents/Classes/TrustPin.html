TrustPin

public final class TrustPin : @unchecked Sendable

TrustPin SSL certificate pinning SDK for Apple platforms.

TrustPin provides SSL certificate pinning functionality to prevent man-in-the-middle (MITM) attacks by validating server certificates against pre-configured public-key pins. The library supports iOS, macOS, tvOS, watchOS, and visionOS with a unified async/await API.

Single-instance usage (simplest)

For most applications a single, shared pinning context is sufficient. Use the static convenience methods — they all delegate to default:

// Setup
try await TrustPin.setup(TrustPinConfiguration(
    organizationId: "my-org",
    projectId:      "my-project",
    publicKey:      "MFkwEwYH...",
    mode:           .strict
))

// Verify (PEM certificate)
try await TrustPin.verify(domain: "api.example.com", certificate: pem)

// URLSession integration
let session = URLSession(
    configuration: .default,
    delegate: TrustPin.makeURLSessionDelegate(),
    delegateQueue: nil
)

Multi-instance usage

Libraries or multi-tenant apps that need isolated pinning contexts can create named instances via instance(id:). Each instance owns its own configuration, state, and log output tagged with the instance id:

let payments = try TrustPin.instance(id: "payments")
try await payments.setup(TrustPinConfiguration(
    organizationId: "payments-org",
    projectId:      "payments-api",
    publicKey:      "MFkwEwYH..."
))
try await payments.verify(domain: "pay.example.com", certificate: pem)

let analytics = try TrustPin.instance(id: "analytics")
try await analytics.setup(/* ... */)

Pinning modes

  • strict: throws domainNotRegistered for unregistered domains (recommended for production).
  • permissive: allows unregistered domains to bypass pinning (development / testing).

All operations are thread-safe.

  • instance(id:)

    Returns the instance registered under id, creating it on first use.

    Calls with the same id always return the same object. The id must match ^[a-zA-Z0-9._-]+$ (ASCII letters, digits, dot, underscore, hyphen); both hyphen-separated identifiers like "mylib-networking" and dot-separated reverse-DNS strings like "com.example.app" are accepted. Instance API

  • setup(_:) Asynchronous

    Configures this instance with the given credentials.

    setup performs local validation only: it checks the credential shapes, parses the public key, stores them, and refreshes the pinning configuration in the background. It never waits for the network, so it throws only invalidProjectConfig or alreadyInitialized. Fetch and validation errors surface from awaitConfiguration(timeout:) — or, fail-closed, from verify(domain:certificate:) at connection time.

    Setup is one-shot: once an instance is configured, further setup calls throw alreadyInitialized. To use different credentials, create a new named instance via instance(id:).

    Recommended fail-closed integration pattern

    If your app must not start networking without a validated pinning payload, gate on awaitConfiguration(timeout:) and treat any error as a hard stop:

    do {
    try await TrustPin.setup(config)                   // local validation only
    try await TrustPin.awaitConfiguration(timeout: 10) // fail-closed gate
} catch {
    // Hard stop. Do NOT fall through to an unpinned URLSession.
    return showRetryUI(error)
}
let session = URLSession(
    configuration: .default,
    delegate: TrustPin.makeURLSessionDelegate(),
    delegateQueue: nil
)

    Apps that prefer zero launch latency can skip the gate — verify is fail-closed and refuses connections whenever the configuration cannot be fetched and validated.

    Throws

    • invalidProjectConfig if any credential is missing, malformed, or empty after trimming, or if another setup call is already in flight on this instance.
    • alreadyInitialized if this instance has already completed setup successfully.

  • awaitConfiguration(timeout:) Asynchronous

    Waits until the pinning configuration has been fetched, signature-verified, and accepted by the integrity check — the explicit fail-closed gate.

    setup(_:) validates credentials locally and refreshes the pinning configuration in the background; it deliberately does not block app launch on the network. Call this method when your integration must not proceed without a validated configuration. Returns immediately when one is already available.

    For a synchronous, non-fetching state read use isConfigurationLoaded.

    Throws

    • invalidProjectConfig if setup(_:) has not completed on this instance.
    • errorFetchingPinningInfo if the configuration cannot be retrieved (transient network failure).
    • configurationValidationFailed if the payload signature does not validate against the configured public key.
    • configIntegrityFailed if the downloaded configuration fails the SDK’s integrity check.
    • timeout if the budget is exhausted.

  • verify(domain:certificate:) Asynchronous

    Verifies a PEM-encoded certificate against the configured pins for domain.

    Uses the default timeout (30 s).

    Throws

    • invalidProjectConfig if the instance has not been set up.
    • invalidServerCert if domain fails input validation or certificate cannot be parsed as X.509.
    • domainNotRegistered if domain is not in the pinning configuration (strict mode only).
    • pinsMismatch if the certificate does not match any configured pin.
    • allPinsExpired if every pin for domain has expired.
    • configIntegrityFailed if a pinning-info refresh fails the integrity check.
    • errorFetchingPinningInfo for transient fetch failures.
    • timeout if the call exceeds the default 30 s.

  • fetchCertificate(host:port:) Asynchronous

    Opens an ephemeral TLS connection to host:port, performs OS-level certificate-chain validation, and returns the server’s leaf certificate as a PEM string.

    Pass a bare hostname (e.g. "api.example.com"), not a URL. The returned PEM string can be passed directly to verify(domain:certificate:). Uses the default timeout (30 s).

    Throws

    • invalidServerCert if host or port fail input validation, or if the TLS handshake produces no leaf certificate.
    • timeout if the call exceeds the default 30 s.
