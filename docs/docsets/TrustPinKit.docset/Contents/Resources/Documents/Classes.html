  • TrustPin

    TrustPin SSL certificate pinning SDK for Apple platforms.

    TrustPin provides SSL certificate pinning functionality to prevent man-in-the-middle (MITM) attacks by validating server certificates against pre-configured public-key pins. The library supports iOS, macOS, tvOS, watchOS, and visionOS with a unified async/await API.

    Single-instance usage (simplest)

    For most applications a single, shared pinning context is sufficient. Use the static convenience methods — they all delegate to default:

    // Setup
try await TrustPin.setup(TrustPinConfiguration(
    organizationId: "my-org",
    projectId:      "my-project",
    publicKey:      "MFkwEwYH...",
    mode:           .strict
))

// Verify (PEM certificate)
try await TrustPin.verify(domain: "api.example.com", certificate: pem)

// URLSession integration
let session = URLSession(
    configuration: .default,
    delegate: TrustPin.makeURLSessionDelegate(),
    delegateQueue: nil
)

    Multi-instance usage

    Libraries or multi-tenant apps that need isolated pinning contexts can create named instances via instance(id:). Each instance owns its own configuration, state, and log output tagged with the instance id:

    let payments = try TrustPin.instance(id: "payments")
try await payments.setup(TrustPinConfiguration(
    organizationId: "payments-org",
    projectId:      "payments-api",
    publicKey:      "MFkwEwYH..."
))
try await payments.verify(domain: "pay.example.com", certificate: pem)

let analytics = try TrustPin.instance(id: "analytics")
try await analytics.setup(/* ... */)

    Pinning modes

    • strict: throws domainNotRegistered for unregistered domains (recommended for production).
    • permissive: allows unregistered domains to bypass pinning (development / testing).

    All operations are thread-safe.
